# MiniPirate OpenOCD Integration & SWD/JTAG Programmer Concept

This document outlines the architecture, hardware adaptation strategies, protocol translation modes, CLI command specifications, and OpenOCD configuration templates required to use MiniPirate as an **ARM Serial Wire Debug (SWD)** and **IEEE 1149.1 JTAG** hardware programmer/debugger.

---

## 1. Overview & Objectives

**OpenOCD (Open On-Chip Debugger)** is the industry-standard open-source tool for hardware debugging, flash programming, and boundary scanning across ARM Cortex-M, RISC-V, MIPS, and legacy ARM targets.

By extending MiniPirate with SWD and JTAG adapter capabilities, standard maker development boards (such as Raspberry Pi Pico, STM32 Nucleo, Seeed XIAO RP2040/RP2350/RA4M1/ESP32-C6, or Arduino Uno) can function as low-cost, multi-protocol hardware debug probes without requiring dedicated expensive debuggers (e.g., SEGGER J-Link, ST-LINK/V2, or FTDI FT2232H boards).

```
+------------------+     USB CDC / Serial / Socket    +--------------------+    SWD / JTAG Bus    +--------------------+
|                  | <=============================> |                    | <==================> |                    |
| Host PC          |   OpenOCD Protocol / Commands    |  MiniPirate MCU    |   SWCLK, SWDIO,      | Target MCU / SOC   |
| (OpenOCD / GDB)  |   (remote_bitbang / BBIO / DAP)  |  (RP2040/STM32/etc)|   TCK, TMS, TDI, TDO | (Cortex-M / RISC-V)|
+------------------+                                  +--------------------+                      +--------------------+
```

### Key Objectives
- **Dual Debug Protocol Support:** Provide physical layer drivers for both **2-wire ARM SWD** (SWCLK, SWDIO) and **4/5-wire JTAG** (TCK, TMS, TDI, TDO, optional nTRST / nSRST).
- **Multiple OpenOCD Interface Protocols:** Implement OpenOCD driver compatibility layers including `remote_bitbang`, Bus Pirate Binary JTAG (`BBIO_JTAG`), and native USB CMSIS-DAP v1/v2 acceleration where supported.
- **Interactive Terminal Debugging:** Expose a human-readable CLI command group (`o` / `mo`) for manual TAP state machine navigation, SWD line reset sequences, register reads, and IDCODE inspection straight from a serial monitor.
- **Hardware Acceleration:** Capitalize on target MCU peripherals—such as RP2040/RP2350 PIO state machines and STM32 direct register GPIO flipping—to achieve fast clock rates (up to 1–5 MHz SWCLK/TCK).
- **Cross-Platform Compatibility:** Abstract pin assignments and physical signal timing across AVR, RP2040, RP2350, STM32, Renesas RA4M1, and ESP32-C6 architectures.

## 2. SWD and JTAG Physical Layer Signals

SWD and JTAG share similar clocking mechanisms but differ significantly in wire count, frame structure, and bidirectional bus handling.

```
                               SWD vs. JTAG Physical Signals
┌──────────────────┬───────────┬──────────────┬────────────────────────────────────────────────────────┐
│ Signal Name      │ Direction │ Protocol     │ Description & Electrical Properties                    │
├──────────────────┼───────────┼──────────────┼────────────────────────────────────────────────────────┤
│ SWCLK / TCK      │ Output    │ SWD & JTAG   │ Clock signal generated by MiniPirate (Host -> Target). │
│ SWDIO / TMS      │ Bi-dir/Out│ SWD / JTAG   │ SWD Bidirectional Data / JTAG Test Mode Select.        │
│ TDI              │ Output    │ JTAG         │ Test Data In (MiniPirate TX -> Target TDI).            │
│ TDO              │ Input     │ JTAG         │ Test Data Out (Target TDO -> MiniPirate RX).           │
│ nSRST            │ Output/OD │ SWD & JTAG   │ System Reset (Active LOW, open-drain with pull-up).    │
│ nTRST            │ Output/OD │ JTAG         │ TAP Controller Reset (Optional active LOW signal).     │
└──────────────────┴───────────┴──────────────┴────────────────────────────────────────────────────────┘
```

### A. ARM Serial Wire Debug (SWD)
SWD replaces the 4-pin JTAG interface with a 2-pin bidirectional protocol:
1. **SWCLK (Serial Wire Clock):** Driven by MiniPirate. Sampled on rising edge by target.
2. **SWDIO (Serial Wire Data Input/Output):** Bidirectional line.
   - **Host Write Phase:** MiniPirate drives SWDIO on SWCLK falling edge.
   - **Turnaround Phase (TRN):** Line tristated for 1 clock cycle to switch drive direction.
   - **Target Read Phase:** Target drives SWDIO (e.g., ACK response or read data packet); MiniPirate reads on SWCLK rising edge.
3. **SWD Line Reset Sequence:** 50+ continuous SWCLK cycles with SWDIO held HIGH, followed by a specific 16-bit switching code (`0xE79E` for JTAG-to-SWD selection) resets the target SWD DP (Debug Port) state machine.

### B. IEEE 1149.1 JTAG Interface
JTAG uses a synchronous 4-wire Test Access Port (TAP) controlled by a 16-state TAP state machine:
1. **TCK (Test Clock):** Clock signal driven by MiniPirate.
2. **TMS (Test Mode Select):** Sampled by target TAP controller on TCK rising edge to navigate TAP states (Test-Logic-Reset, Run-Test/Idle, Select-DR-Scan, Shift-DR, etc.).
3. **TDI (Test Data In):** Serial data shifted into instruction/data registers on TCK rising edge.
4. **TDO (Test Data Out):** Serial data shifted out of target on TCK falling edge; read by MiniPirate on TCK rising edge.

## 3. System Architecture & Protocol Translation Modes

MiniPirate supports four distinct operational integration modes for OpenOCD and host tools:

```
                          MiniPirate OpenOCD Translation Modes
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ Mode 1: OpenOCD remote_bitbang Interface (TCP / Serial Stream)                                 │
│ OpenOCD ASCII Commands ('B', 'b', '0'..'7', 'R') === USB CDC ===> MiniPirate Pin Flipping Engine│
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Mode 2: Bus Pirate Binary JTAG Emulation Mode (BBIO_JTAG)                                      │
│ OpenOCD buspirate.c Driver === Binary Packets (0x00, 0x10, 0x40) ===> MiniPirate Mode Switch    │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Mode 3: CMSIS-DAP v1/v2 USB HID/Bulk Bridge Mode                                               │
│ OpenOCD cmsis_dap.c Driver === USB Packets (0x00-0x2D) ===> High-Speed Native USB Protocol     │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Mode 4: Standalone Interactive CLI Debug Sub-Mode ('mo' / 'o')                                  │
│ Human User Terminal === CLI Commands ('o id', 'o reset', 'o shift') ===> Direct TAP Execution  │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### Mode 1: OpenOCD `remote_bitbang` Interface
OpenOCD includes a built-in `remote_bitbang` driver (`src/jtag/drivers/remote_bitbang.c`) that sends simple ASCII character commands over a socket or serial terminal line:
- `'B'` / `'b'`: Enable / disable LED / status output.
- `'0'` .. `'7'`: Set signal states:
  - Bit 0: TCK / SWCLK value
  - Bit 1: TDI value
  - Bit 2: TMS / SWDIO value (when writing)
  - Bit 3: nSRST value
  - Bit 4: nTRST value
  - Bit 5: SWDIO Direction (1 = Output, 0 = Input)
- `'R'`: Sample and return current TDO or SWDIO input bit ('0' or '1').
- `'Q'`: Quit connection.

*Advantage:* Simple to implement across all microcontroller families without custom USB HID driver stacks.

### Mode 2: Bus Pirate Binary JTAG Emulation Mode (`BBIO_JTAG`)
MiniPirate can emulate the Bus Pirate binary mode interface (`buspirate.c` in OpenOCD):
1. **Entry Sequence:** Send 20 raw `0x00` bytes over serial to enter binary mode (`BBIO1`).
2. **JTAG Mode Select:** Send byte `0x06` to enter `JTAG1` mode.
3. **Hardware Commands:**
  - `0x00`: Reset TAP controller
  - `0x10`..`0x1F`: Write TMS/TDI bits and clock TCK
  - `0x40`..`0x7F`: High-speed byte-level TDI/TDO shift engine
  - `0x02` / `0x03`: Drive / release reset pins (nSRST / nTRST)

*Advantage:* Out-of-the-box support in standard OpenOCD releases via `interface buspirate`.

### Mode 3: CMSIS-DAP v1/v2 USB Bridge Mode
For microcontrollers with native USB engines (RP2040, RP2350, STM32, ESP32-C6, RA4M1), MiniPirate provides a dedicated USB CDC/HID endpoint implementing the ARM CMSIS-DAP v1/v2 protocol:
- Direct USB transfers without serial character parsing overhead.
- Operates at native USB 12 Mbps / 480 Mbps speeds.
- Native integration with OpenOCD (`interface cmsis-dap`), PyOCD, and Keil MDK.

### Mode 4: Standalone Interactive CLI Debug Sub-Mode (`mo` / `o`)
Provides a manual command shell for hardware hackers to probe unknown targets, read JTAG IDCODEs, or force target resets directly from PuTTY or Minicom without launching OpenOCD.

## 5. Platform-Specific Hardware Acceleration Techniques

To minimize protocol latency and achieve high debug frequencies, platform-specific hardware acceleration techniques are utilized:

### A. RP2040 / RP2350 PIO State Machine Acceleration
The RP2040/RP2350 Programmable I/O (PIO) blocks execute state machine programs independently of the main ARM Cortex-M0+/M33 cores:

```asm
; PIO SWD Shift Program (RP2040 / RP2350)
.program swd_shift
.side_set 1 ; Side-set bit 0 controls SWCLK

; Shift out OSR to SWDIO on falling edge, sample SWDIO into ISR on rising edge
public shift_out:
    out pins, 1        side 0 [1] ; Drive SWDIO bit, SWCLK LOW
    nop                side 1 [1] ; SWCLK HIGH, target samples
    jmp x-- shift_out  side 1 [0]

public shift_in:
    set pindirs, 0     side 0 [1] ; Tristate SWDIO (Input mode), SWCLK LOW
loop_in:
    in pins, 1         side 1 [1] ; Sample SWDIO into ISR, SWCLK HIGH
    jmp y-- loop_in    side 0 [1] ; SWCLK LOW
```

- **Performance Gain:** Shifts SWD data packets at up to **10 MHz** with zero CPU clock intervention during bit transfers.

### B. STM32 Direct Register GPIO Manipulation
For STM32 (Cortex-M4), standard `digitalWrite()` calls introduce 20–50 clock cycles of overhead per pin toggle. Fast atomic bit set/reset registers (`BSRR`) are used instead:

```c
// Direct BSRR register toggling for STM32
#define SWCLK_HIGH()  (GPIOA->BSRR = GPIO_BSRR_BS5)
#define SWCLK_LOW()   (GPIOA->BSRR = GPIO_BSRR_BR5)
#define SWDIO_HIGH()  (GPIOA->BSRR = GPIO_BSRR_BS6)
#define SWDIO_LOW()   (GPIOA->BSRR = GPIO_BSRR_BR6)
#define READ_SWDIO()  ((GPIOA->IDR & GPIO_IDR_ID6) != 0)
```

- **Performance Gain:** Reduces bit-bang time from ~1.2 µs down to **20 ns per clock edge** (~5 MHz clock rate).

## 6. MiniPirate CLI Command Specification (`o` Command Group)

The `o` command group governs SWD/JTAG debug modes and status commands:

```
                                SWD / JTAG CLI Commands
┌──────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────────────┐
│ Command          │ Syntax                                   │ Description / Example                            │
├──────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────────────┤
│ Mode Select      │ `mo` or `m o`                            │ Enters SWD / JTAG debug mode context             │
│ Select Protocol  │ `o m [swd|jtag|remote|bbio|dap]`         │ Configures debug sub-mode                        │
│ Read IDCODE      │ `o id`                                   │ Performs SWD/JTAG scan & prints target IDCODE    │
│ Target Reset     │ `o reset [srst|trst|sys]`                │ Asserts reset signals or executes SWD reset      │
│ Pin Mapping      │ `o p [signal] [pin]`                     │ Reassigns SWCLK, SWDIO, TDI, TDO pins            │
│ Set Clock Speed  │ `o f [speed_khz]`                        │ Sets target clock speed in kHz (e.g., `o f 1000`)│
│ Shift Raw Bits   │ `o s [nbits] [hex_data]`                 │ Shifts `nbits` through SWD/JTAG register         │
│ Read AP/DP Reg   │ `o r [dp|ap] [addr]`                     │ Reads ARM Cortex SWD Debug/Access Port register  │
│ Write AP/DP Reg  │ `o w [dp|ap] [addr] [val]`               │ Writes value to SWD Debug/Access Port register   │
│ Show Status      │ `o` or `o ?`                             │ Displays SWD/JTAG pin states and active mode     │
└──────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────────────┘
```

## 7. OpenOCD Configuration Script Templates

To integrate MiniPirate with standard OpenOCD setups, save the following configuration files to your workspace.

### A. Template 1: `minipirate_remote_bitbang.cfg` (OpenOCD Remote Bitbang Driver)

```tcl
# OpenOCD Configuration for MiniPirate via remote_bitbang interface
adapter driver remote_bitbang

# Select transport protocol: 'swd' or 'jtag'
transport select swd

# Specify connection host and port or serial pipe driver
# Option A: Direct TCP connection if MiniPirate USB serial bridge is piped
remote_bitbang port 3335
remote_bitbang host 127.0.0.1

# Set SWD / JTAG clock frequency (in kHz)
adapter speed 1000

# Target definition (Example: STM32F4 series)
source [find target/stm32f4x.cfg]
```

### B. Template 2: `minipirate_buspirate.cfg` (Bus Pirate Binary Mode Emulation)

```tcl
# OpenOCD Configuration for MiniPirate emulating Bus Pirate JTAG/SWD
adapter driver buspirate

# Set serial port device path
buspirate port /dev/ttyACM0

# Set serial baud rate (115200 or 57600)
buspirate speed 115200

# Power supply and pull-up defaults (0 = off, 1 = on)
buspirate vreg 0
buspirate pullup 0

# Select transport protocol
transport select jtag

# Set target clock speed
adapter speed 500

# Target definition (Example: Raspberry Pi RP2040)
source [find target/rp2040.cfg]
```

### C. Template 3: `minipirate_cmsis_dap.cfg` (CMSIS-DAP v1/v2 Direct USB Driver)

```tcl
# OpenOCD Configuration for MiniPirate running CMSIS-DAP firmware
adapter driver cmsis-dap

# Select CMSIS-DAP transport mode: swd or jtag
transport select swd

# Specify device VID/PID (Example: MiniPirate CMSIS-DAP VID/PID)
cmsis_dap_vid_pid 0x1209 0x0001

# Set adapter speed in kHz
adapter speed 2000

# Target definition (Example: Nordic nRF52840 / Cortex-M4)
source [find target/nrf52.cfg]
```

## 9. Configuration Persistence & EEPROM Integration

In alignment with MiniPirate's existing state storage mechanism (`x` to save, `y` to restore):

1. **Saved Debug Parameters:** Executing `x` persists active SWD/JTAG pin mappings (`SWCLK`, `SWDIO`, `TDI`, `TDO`, `nSRST`), default target clock speed, and preferred sub-mode (`swd`, `jtag`, `remote_bitbang`, `cmsis-dap`) to EEPROM / Flash NVS.
2. **Boot Restoration:** Executing `y` or powering up with auto-restore enabled automatically configures the designated GPIO pins into SWD/JTAG driver modes and initializes PIO / timer registers.
